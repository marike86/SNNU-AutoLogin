# Windows 校园网检测路径修复

验证日期：2026-10-27。此记录对应 Windows v1.0.1 小版本更新。

## 问题与修复

本机校园 Wi-Fi 已认证，但默认到 `202.117.144.205` 的路径经过 FlClash 虚拟接口，原版状态查询超时并显示“等待校园网”。在同一时段，绑定校园 Wi-Fi 地址的只读请求能返回包含在线账号标识的真实状态页。

Windows 的门户状态、登录、登录页和下线请求现在逐连接选择当前物理网络 IPv4 地址，通过绑定本地 socket 访问；优先 Wi-Fi，排除已识别的 VPN、虚拟以太网与 USB 手机共享接口。不修改代理配置或系统路由，不缓存旧网卡地址。物理路径连接失败时不偷偷切换到其他网络重发该连接。回环测试服务器保持走回环接口。

保留公共外网检测原有的 DNS/代理路径，避免 TUN 合成 DNS 地址被发送到物理网络后产生新的检测失败。此次修复并不宣称公共外网探测能区分多网卡上的每一条出口。

使用上游 ureq 2.12.1 的本地副本，增加可选的 TCP 连接回调；说明与许可证见 `vendor/ureq/LOCAL-CHANGES.md`。未替换 HTTP、字符解码、Cookie 或认证解析实现。macOS 不启用该回调。

## 已通过

- Windows Debug 与 Release：75 项回归测试通过，0 失败，1 项需校园网的测试默认忽略。新增检查覆盖物理网卡筛选、绑定源地址与回环请求。
- 在 FlClash 保持运行、校园 Wi-Fi 与 USB 手机共享同时存在时，显式运行只读校园网检查，约 0.07 秒识别为在线。未提交密码或发送下线请求。
- 最终优化 EXE 的 `--probe` 在独立空配置目录下运行，退出码 0，识别为在线；未读取用户保存的密码。
- 修改的 Windows Rust 源文件通过格式与差异空白检查；第三方许可证报告生成成功。

## 交付与边界

`dist/SNNU-AutoLogin.exe` 与 `dist/SNNU-AutoLogin-v1.0.1-windows-x64.zip` 为正式打包产物，附许可证、第三方说明与 SHA256。请从托盘退出旧版后启动，沿用原有用户配置。

发布构建基于 main 分支，独立验证 Windows 打包流程，不包含正在开发的 macOS 或 Android 改动。
